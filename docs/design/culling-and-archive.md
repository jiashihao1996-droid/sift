# 筛图交互与归档重设计

状态：已全部实现——#26 标记模型与键位、#27 归档布局、#28 反馈、#29 缩放与预加载、清理死代码（本节末项）。
起草：2026-10-03

## 背景

- 「跳过」实际承担两件事：记录「看过」（进度、标记后跳到下一张未处理、总结卡），以及归档时「保留」（精选 + 跳过移入 `JPG/`、`RAW/`，未处理留原位）。
- `→` / `Space` 是 `markSkip`，回看时会把 ★、删除改成跳过；没有纯前进键。
- 标记后跳到「下一张未处理」，回看时改一张会被甩到前沿；取消标记不进撤销栈。
- `slideDirection` 是死状态（上游 6998a4c 删掉了 slide `<Transition>`），PR #24 修的值没人读。

结论：去掉「跳过」，也不引入隐式的「看过」状态。照片只有 **精选 / 删除 / 未标记** 三种状态。

## 归档（已定）

| 状态   | JPG                             | RAW          | XMP                                        |
| ------ | ------------------------------- | ------------ | ------------------------------------------ |
| 删除   | 进系统回收站（`trash::delete`） | 进回收站     | 进回收站                                   |
| 未标记 | 原地不动                        | 移入 `RAW/`  | 跟 RAW 进 `RAW/`；无 RAW 时随 JPG 原地不动 |
| 精选   | 移入 `精选/`                    | 移入 `精选/` | 移入 `精选/`                               |

```
DCIM-0915/
├── DSC_0002.JPG          ← 未标记：JPG 原地
├── RAW/
│   └── DSC_0002.ARW      ← 未标记的 RAW（+ XMP）
└── 精选/
    ├── DSC_0003.JPG      ← 精选：JPG + RAW + XMP 同一文件夹
    └── DSC_0003.ARW
```

细则：

1. **删除不是永久删除**，仍只用 `trash::delete`（项目安全规则）。例外（2026-10-03 定）：没有回收站的位置（网络共享；Windows 上的 FAT/exFAT 存储卡）在归档对话框醒目警告，用户每次勾选确认后才永久删除；macOS 继续用「访达」方式进废纸篓，以保留「放回原处」。
2. **扫描纳入 `RAW/` 子文件夹参与配对**：重开原文件夹时，原地 JPG 与 `RAW/` 中同 stem 的 RAW 重新配对；删除时一起进回收站；再次归档时已在 `RAW/` 的文件不动。否则重开后全是「无 RAW」，删 JPG 会留下孤儿 RAW。
3. **重名不覆盖、保持配对**：未标记照片的 RAW 在 `RAW/` 中重名而加 `_N` 时，原地的 JPG（和随 JPG 的 XMP）同步改名为同一 `_N`（同目录改名，同样先 `create_new` 占位）。`精选/` 内三者同目录，沿用 `paths::unique_paths_sharing_stem` 的共用后缀规则。
4. **纯 RAW**：精选 → RAW 进 `精选/`，并把缓存预览图存为同名 JPG 放在旁边（与现有归档一致）；未标记 → 只把 RAW 移入 `RAW/`，不往原文件夹写新文件（靠第 2 条重开时仍可见）。
5. **文件夹名**：`精选`。
6. **导出保留**：只导出精选，复制到用户选择的目录，行为不变。
7. **归档确认框**写明：精选 X 组 → `精选/`；删除 Y 组 → 回收站；其余 Z 组：JPG 不动，RAW → `RAW/`。
8. 筛到一半也可以归档：未标记的 JPG 留在原地，重开原文件夹可继续筛。归档成功后清除该文件夹的进度（同现状）。
9. 不再有 `JPG/` 文件夹。
10. 改动 archive / scan 必须附带临时目录的 Rust 测试（项目规则）。
11. **只删除，不整理**（2026-10-03 定）：归档对话框另有一个按钮，只处理标记删除的照片（进回收站，或在没有回收站的位置经确认后永久删除），其他文件都不移动，删完会话照常可用。不做「撤销整次归档」。
12. **重新打开含 `精选/` 的文件夹**（2026-10-05 定，见下一节）。

## 重新打开含 `精选/` 的文件夹（2026-10-05 定）

需求：归档后再打开父文件夹，`精选/` 里的照片继续参与浏览、对比（时间线、连拍分组、Survey），只是默认带上精选标记。

扫描：

- 只额外读取 `精选/` 这一层；`精选/RAW/`、`精选/精选/`、`精选/JPG/` 等子文件夹不读（与「其他子文件夹不读」一致）。
- `精选/` 单独建索引、单独配对，XMP 也只在 `精选/` 内认领。原位、`RAW/`、`JPG/` 之间照旧互相配对，但永远不和 `精选/` 里的同名文件配。
- 纯 RAW 归档时另存的 `<stem>.jpg` 和 RAW 在同一层，扫描时就是一组普通的 JPG + RAW，只算一条。
- 这些条目 `isArchivedPick = true`，状态默认精选。不做「已归档」标识，归档确认框也不分项计数。

进度：只保存与默认不同的标记（`progress.ts::defaultStatus`），所以取消已归档的精选会存成「未标记」；恢复时已保存的标记优先；「重新开始」把它们恢复成精选。key 是 `精选/` 下的路径。

再次归档（原则：归档完成后，文件在哪个文件夹就说明它是什么状态）：

| 状态 \ 位置  | 原位 / `RAW/`（不变）             | `精选/` 里（已归档的精选）                                                |
| ------------ | --------------------------------- | ------------------------------------------------------------------------- |
| 精选         | 移入 `精选/`，重名时整组共用 `_N` | 不动、不改名                                                              |
| 未标记       | JPG 不动，RAW + XMP → `RAW/`      | JPG 回原位，RAW + XMP → `RAW/`（无 RAW 时 XMP 跟 JPG）；重名整组共用 `_N` |
| 删除         | 回收站（`TrashOrRemove`）         | 同左                                                                      |
| 只删除不整理 | 只删标记删除的                    | 同左；取消精选的留在 `精选/`，等下次归档（进度里记着）                    |
| 导出         | 复制精选                          | 同样复制（导出 = 当前所有精选）；永不覆盖                                 |

配对范围：`精选/` 与「原位 + `RAW/` + `JPG/`」是两个配对范围。文件跨范围移动时（新精选移入 `精选/`，取消精选的移回），目标范围里只要已有同 stem 的别的照片（任一文件夹、任一扩展名，只折叠 ASCII 大小写），就算重名、整组改用下一个 `_N`（`organize/pair_scopes.rs`）；否则比如原位的 `DSC_2.JPG` 会和移回 `RAW/` 的另一张 `DSC_2.ARW` 配成一组，删除一张就会连带另一张。进度 key 对有 RAW 的已归档精选用 RAW 路径，预览被丢弃后 key 不变。

纯 RAW 的预览：取消精选时不回原位（原位从来没有这个 JPG），而是丢弃，下次再精选时重新生成。只有 JPG 与 RAW 只差扩展名、且与从 RAW 重新提取的内嵌预览逐字节相同时才算预览（`organize/saved_preview.rs`），内容来自 RAW，丢弃不丢信息；被编辑过的或旧版本生成的对不上，当作用户的 JPG 移回原位。丢弃走 `TrashOrRemove`：没有回收站的位置要在这次归档勾选永久删除（对话框在有可能丢弃预览时显示确认）。顺序是先丢预览、再移 RAW：丢弃失败则这组不动；移动失败回滚后 RAW 留在 `精选/`，重新扫描仍是精选，预览会重新提取。

## 标记与交互（已定）

- 状态：精选 / 删除 / 未标记。去掉「跳过」：键位、ActionBar 按钮、状态栏、筛选图库、总结卡、README、快捷键帮助一并去掉。
- `F` 切换精选；`X` / `Delete` 切换删除；去掉 `Backspace`。两键之间可直接互换。
- 标记或换标记后前进到下一张（i+1）；不再跳「下一张未处理」，也不回绕。
- 取消标记（再按同一键）停在当前照片。
- 「标记后停在当前照片」开关（2026-10-03 增补）：`L` 切换，默认关闭；开启时标记、换标记也停在当前照片，用于连拍组内对比。状态作为 viewer 偏好存 localStorage（`sift.stayAfterMark`），与按文件夹存的进度分开；开启时状态栏显示「停留」标识（可点击关闭），切换时 toast 提示一次。开启时在最后一张标记不算「再前进」，不弹总结卡；撤销规则不变。
- `←` / `→` / `Space` 纯导航，允许按住连发；`F` / `X` / `Delete` 忽略 `e.repeat`。
- 撤销：标记、换标记、取消标记各算一步；撤销恢复原状态并跳回那张；不做重做，`Cmd+Shift+Z` 不再触发撤销；撤销栈为空时不提示「已撤销」。
- 进度：保存标记与当前位置；没有标记但位置不在第一张时也保存；旧进度文件中的 `skipped` 视为未标记，其余标记照常恢复。
- 进度条按位置（第 N 张 / 总数）。
- 删除 `slideDirection`、`slideDirectionTo`、slide CSS、`activePairs`，保持瞬时切换。

- 标记反馈：底部短提示「★ 精选 · 文件名 · 撤销」约 1.2 秒，新的替换旧的（修 `showToast` 计时器不清理）；主图常驻状态角标，替换写反的删除闪烁；ActionBar 按压动效对键盘标记也生效。
- 按钮位置（2026-10-05 定）：照片上不放常驻控件。精选 / 删除（ActionBar）和旋转 / Survey / 对比（ViewerTools）放在顶栏右侧，顺序为「标记 | 视图工具 | 归档、快捷键、EXIF」；窗口宽度小于 1024px 时按钮收起文字，只留图标和键位，文件名先让出空间。标记提示贴着底部缩略条。对比模式下顶栏文件名显示当前图（F / X 作用的那张），不再显示基准图。比较过并入底部状态栏、自动隐藏、左侧竖排工具条，选顶栏是因为它和其他全局操作在一起、不占图片区。栏高度只在 `main.css` 的 `--nav-bar-h` / `--thumb-strip-h` / `--status-bar-h` 定义。
- 总结卡：在最后一张上再前进（→ / Space / 标记）时弹出；「继续浏览」关闭，回看改标记不再弹。
- 切换照片时保持缩放比例与位置，旋转仍复位。
- 触控板与滚轮（2026-10-04 增补，修「缩放太灵敏」）：
  - 实测（macOS WKWebView）：捏合 = 带 `ctrlKey` 的 wheel 事件，约 8ms 一个，deltaY 是 0.1–3 的小数，同时还发 Safari 的 `gesturechange`（不用）；`exp(-ΣdeltaY/100)` 与手指的 `scale` 一致。双指滑动 = 不带 `ctrlKey` 的 wheel，deltaY 是 1–5 的整数，带约 0.5 秒惯性尾巴。全部 `deltaMode = 0`。
  - 规则在 `src/core/wheel.ts`：捏合 `zoom *= exp(-deltaY/100 × 1.5)`（`exp(-deltaY/100)` 是手指本身的倍数，1:1 用户试用觉得偏慢，取 1.5 倍增益，d3-zoom 约 1.4）；鼠标滚轮每格 ×1.2（macOS 一格是 4.000244 px 的倍数，Windows 是 `wheelDeltaY` ±120 的倍数，行模式 3 行一格），每个事件最多算 3 格；认不出的一律当触控板滑动（宁可平移也不乱缩放）。Windows 的识别规则未实测。
  - 双指滑动 = 放大后平移（macOS 看图惯例），适应窗口及以下不动；平移止于图片边缘（`zoom.ts::panByScroll`），之前拖出边界的不回弹。拖拽平移不受限，行为不变。
  - 软吸附（`zoom.ts::settleOnDetents`）：一次连续手势经过适应窗口（1）和 100%（`actualZoom`）时停住，继续推 `ln(1.1)`（约 10%）才越过；事件间隔超过 200ms 算新手势，从停住的位置出发可以自由离开。按键缩放不吸附。
  - 手势进行中（含 200ms 尾巴）不用 CSS transition，按键和双击仍有 260ms 过渡。
  - `MIN_ZOOM` / `MAX_ZOOM` 不变：问题在映射，不在范围。
- 预加载：按前进方向预载接下来几张、后面 1 张；用 `decode()`；改成真正的 LRU。
